# M2全历史财务补全：来源与验收规则

权威配置是[冻结配置](../configs/factors/m2_alternate_history.json)，在批量采集前提交。用户授权AKShare替代路线后，原研究股票、季度、字段及因子准入规则保持不变。

原清单包含726只历史CSI300股票、20,260个股票季度，盈利/成长两接口合计40,520个股票—接口—季度。987个股票—接口历史的BaoStock缓存完整，继续使用；465个不完整历史整体使用东方财富重建，覆盖233只股票。选择只依据缓存完整性，不依据收益或因子强弱。另选10只排序等距的完整历史股票作跨源对照。

每个股票—接口仅使用一种来源，保留`source_assignment.csv`。原始响应分别存放在`data/raw/baostock`和`data/raw/eastmoney_m2`；没有给东方财富响应生成BaoStock缓存键，也没有伪造原缺失请求的完成数量。可以完成原数据范围的交付，不代表BaoStock限制已经解除。

东方财富表使用AKShare源接口中的通用、银行、证券、保险资产负债表，以及利润表。每批10只股票、每页200条，串行请求间隔至少1秒，无自动重试；参数和响应均缓存、校验哈希，分页总数和股票/日期范围必须一致。只请求2006年至2020年上半年报告、公告不晚于2020-07-31；2006年仅为年初权益依赖和统一请求范围，不用于扩展收益研究。

平均ROE由归母净利润和年初、期末归母权益计算；普通报表净利率由合并净利润除以营业收入，银行/证券/保险报表使用包含金融业务的完整营业总收入。三个同比沿用对应报表的合并净利润、总资产、归母权益同比字段并除以100。分母为零或所需数值缺失时保留缺失，不修方向，不用加权ROE或归母净利润增长替代不同口径。

每个字段独立处理可用时间。首次批量核对发现确定的追溯改写后，主面板改为保守地取所有依赖NOTICE_DATE和UPDATE_DATE的最大值，信号日必须严格晚于该时间。先在首次公告时产生缺失事件，依赖及版本时间齐备后才出现数值，防止沿用旧报告。UPDATE_DATE缺失时不放行当前数值。仍按最新财报期优先，可用时间年龄400天、财报期年龄550天限额处理。来源没有报告时记录缺口，不编造公告日期。

原始返回中的1900年公告占位值不得进入面板。采集保留并隔离无效日期；若它属于原计划报告或必要年初权益依赖，则构建失败，必须先解决。若完全在原计划及依赖之外，则记录排除原因，不扩大研究范围。

`NOTICE_DATE`与`UPDATE_DATE`分别保留；更新日期晚于公告的记录加标识。更新日期只是保守版本时间限制，不冒充首次公告，也不能恢复原始历史版本。纯公告对齐只用于跨源数值差异诊断，不是新替代源主面板。BaoStock完整历史保持原冻结的公告对齐、修订未知口径，两个来源的时间假设不同，必须随来源表披露。所有缺失都保留，不为了覆盖率放松限制。

修正依据与作废run见[数据口径审计](M2_ALTERNATE_SOURCE_AUDIT.md)。修正只依据原始响应与公司公告，没有检查或优化新因子收益。

验收分别检查：请求成功与分页完整；原40,520项逐项核销；所有五字段事件直接从原始源重算；规范市场成员范围重建；所有逐日面板单元独立重放。覆盖率、缺失报告、跨源差异和日期异常均应随报告交付。独立验收不依赖生成器的公式或as-of函数。

这批只补全数据和验收，不复活已拒绝的ROE/成长/投资公式，不改既有BP/现金流模型的NO_GO结论，不打开资格期或锁箱。
